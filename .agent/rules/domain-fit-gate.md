# .agent/rules/domain-fit-gate.md\n\n## Purpose\n\nThis gate is MANDATORY and BLOCKING. It runs BEFORE workflow.md for every job posting.\n\nIts job is to determine whether the candidate is eligible to proceed based on the facts in master-profile.md.\n\nNO CV, cover letter, PDF, tracker entry, execution record, or application work may be created for a job that this gate marks SKIP.\n\n## Non-negotiable source of truth\n\n- master-profile.md is the only source of candidate facts.\n- A requirement is satisfied only when master-profile.md contains explicit evidence supporting it.\n- Never upgrade, reinterpret, or infer candidate facts:\n  - fluent != native\n  - lead generation != SDR tenure\n  - having a CRM in Skills != demonstrable daily CRM experience\n  - prospecting != closing / Account Executive experience\n  - B2B exposure != industry-specific experience\n  - being able to learn a tool != already meeting an explicit experience requirement\n- If the JD requires a fact that the profile does not explicitly establish, it is a gap, not a match.\n- Never write that the candidate meets a requirement when the profile does not explicitly prove it.\n\n## Step 1 — Extract ALL requirements before judging fit\n\nRead the entire JD and build a requirement checklist.\n\nClassify every requirement as:\n1. HARD requirement — required, mandatory, essential, must, must have, indispensable, imprescindible, obligatorio, minimum, at least, or an explicit statement such as “if you do not have X, this position is not for you”.\n2. PREFERRED / nice-to-have — preferred, plus, nice to have, bonus, a plus, appreciated, ideal.\n3. GENERAL / learnable — a skill or tool that is explicitly not a hard prerequisite.\n\nWhen the JD uses strong language, treat it as hard even if the requirement appears in prose rather than under Requirements.\n\n## Step 2 — HARD REQUIREMENT SATISFACTION TEST\n\nFor EVERY hard requirement, ask:\nCan I point to an explicit fact in master-profile.md that proves this requirement is satisfied?\n\n- YES → MATCH.\n- NO → MISMATCH / UNVERIFIED.\n\nDo not use overall similarity, keyword overlap, LinkedIn labels, or the fact that the candidate could learn something to convert a mismatch into a match.\n\n### Experience and tenure\n\nNumeric or categorical thresholds are literal.\n\nExamples:\n- JD: “2+ years as an SDR” → profile must explicitly support 2+ years as an SDR.\n- JD: “1+ year of outbound sales” → profile must explicitly support at least 1 year of outbound sales.\n- JD: “native Spanish” → profile must explicitly say native Spanish. Fluent Spanish does not satisfy it.\n- JD: “daily HubSpot experience” → profile must explicitly support actual HubSpot use; merely listing HubSpot in Skills is not enough to claim daily.\n- JD: “experience closing deals” → prospecting/lead generation alone does not satisfy closing experience.\n\n### Language requirements\n\nLanguage level must match literally unless the JD explicitly allows an equivalent level.\n- native Spanish requires native Spanish in the profile.\n- fluent Spanish can match fluent Spanish.\n- professional Spanish can match professional Spanish when the profile supports it.\n- Never convert one level into another.\n\n### Work authorization / location\n\nThe candidate work authorization is ONLY Spain as stated in master-profile.md.\n- Explicit Spain authorization requirement → match only if the role location/eligibility is Spain.\n- Any other country-specific authorization or required physical presence outside Spain → mismatch unless the JD explicitly allows contractor/EOR/location-agnostic hiring without that country authorization/residency.\n- EU membership does not imply EU-wide work authorization.\n\n## Step 3 — Absolute blockers\n\nThe following are immediate blockers when the profile does not satisfy them:\n- Any explicit minimum years/tenure requirement.\n- Any explicitly mandatory language level that is not supported.\n- Any explicit country-specific work authorization requirement that is not supported.\n- Any mandatory degree/certification/license that is absent.\n- Any mandatory industry/domain experience absent from the profile.\n- Any mandatory network/relationship requirement absent from the profile.\n- Any mandatory named-tool experience when the JD requires prior demonstrated experience and the profile does not establish it.\n- Any other requirement explicitly stated as essential/indispensable/must-have.\n\nIf ANY absolute blocker is a mismatch or unverified, status is SKIP.\nDo not proceed to overall fit or try to compensate for a hard blocker with strengths elsewhere.\n\n## Step 4 — Learnable skills are NOT blockers only when they are actually learnable\n\nA tool, CRM, methodology, product, or technical concept may be learnable ONLY when the JD does not make prior experience with it a hard requirement.\n\nExamples:\n- Familiarity with Salesforce preferred → not a blocker.\n- Experience using Salesforce required + profile does not establish Salesforce experience → SKIP.\n- Understanding of API integrations → learnable if not framed as prior experience/minimum tenure.\n- 2 years selling SaaS required → not learnable for the purpose of this gate; if unsupported → SKIP.\n\n## Step 5 — Specialized domain / network checks\n\nThese are also hard blockers when mandatory and absent:\n- specialized non-IT domain experience (e.g. pharma, CRO, healthcare compliance, legal, regulated finance)\n- established network / existing relationships\n- mandatory industry-specific customer portfolio\n\nIf absent → SKIP.\n\n## Step 6 — Compensation gate\n\nCommission-only / no-base compensation remains an immediate SKIP.\n\nTrigger phrases include:\n- commission-only\n- 100% commission\n- straight commission\n- commission-based\n- uncapped commission\n- no base salary\n- draw against commission only\n- 1099 commission-only\n\nIf a trigger appears and the JD contains no fixed base salary/base pay/fixed salary/base + commission/base + OTE → SKIP.\n\nIf a fixed base is explicitly stated elsewhere, compensation is not a blocker.\n\nIf compensation is completely undisclosed, do not invent a conclusion; put it in the gap report.\n\n## Step 7 — Status decision\n\nUse exactly one of these statuses:\n\n### SKIP\nUse when ANY hard requirement is not explicitly satisfied.\n\nRequired output:\n- Status: SKIP\n- exact JD quote(s) for each blocking requirement\n- corresponding profile evidence, or explicitly state: No supporting evidence in master-profile.md\n- one-line reason\n\nDo NOT generate CV/CL/PDF/tracker/record.\n\n### PROCEED\nUse only when:\n- every hard requirement is explicitly satisfied, and\n- no compensation/location/industry/network blocker exists.\n\nSoft gaps may remain.\n\n### PROCEED_WITH_GAPS\nUse only when:\n- every hard requirement is satisfied, but\n- one or more preferred/nice-to-have items are missing.\n\nNever use PROCEED_WITH_GAPS to bypass a hard requirement.\n\n## Step 8 — Mandatory pre-generation checkpoint\n\nBefore drafting anything, print a compact gate result:\n\n| Requirement | Type | Profile evidence | Result |\n|---|---|---|---|\n| ... | HARD/PREFERRED | exact profile fact or none | MATCH/MISMATCH |\n\nThen apply this rule:\nIF ANY HARD row is MISMATCH/UNVERIFIED → STOP this job immediately with SKIP.\n\nNo gap report but apply anyway.\nNo overall fit is strong, so proceed.\nNo the candidate can learn it.\nNo exception based on urgency, job quality, or keyword match.\n\n## Calibration examples\n\n### Pilatus-style SDR\nJD:\n“Minimum 2 years as SDR. If you have not worked as SDR at least 2 years, this position is not for you.”\n\nProfile:\n- Founder & Lead Generation Specialist — CLG Project, Jul 2025–Present\n- No prior SDR title / 2 years SDR tenure in master-profile.md\n\nResult: SKIP. The 2-year SDR requirement is a literal hard blocker.\n\nIf the same JD also says:\n“Native Spanish indispensable.”\n\nProfile:\n“Spanish — fluent”\n\nResult: SKIP. Fluent is not native.\n\nIf the JD says:\n“Demonstrable daily HubSpot experience.”\n\nProfile only lists:\n“HubSpot/Salesforce” under Skills\n\nResult: Do not claim daily HubSpot experience. If daily is explicitly mandatory, SKIP because the profile does not prove it.\n\n### Bitdefender-style SDR\nJD:\n- English + Spanish fluency required.\n- Outbound/inbound prospecting and CRM work.\n- No minimum SDR tenure stated.\n\nProfile:\n- English fluent\n- Spanish fluent\n- outbound prospecting / lead generation\n- CRM tools listed and supported by CLG experience\n\nResult: PROCEED, assuming no other hard blocker exists.\n\n### WIN SOURCE-style early-career sales\nJD:\n- electronics experience not required\n- fresh graduates welcome\n- B2B preferred, not required\n- Spain work authorization required\n\nProfile:\n- Spain work authorization\n- B2B lead generation\n- BSc student\n\nResult: PROCEED.\n\n### Revolut-style commercial role\nJD:\n“1+ years demonstrable commercial experience, particularly outbound sales and prospecting.”\n\nProfile:\n- CLG Project Jul 2025–Present with outbound prospecting / lead generation\n\nResult: PROCEED only if the dates in the profile/JD context establish at least 1 year at the time of application. Do not round or invent tenure.\n\n## Important\n\nThis gate is intentionally stricter than a generic job-match system.\n\nHARD REQUIREMENTS ARE GATES, NOT SUGGESTIONS.\n\nThe agent strengths, keyword match, confidence, or ability to learn do not override a hard requirement.\n\nWhen in doubt about whether a requirement is hard, use the stronger interpretation if the JD uses mandatory language. When in doubt about whether the profile proves it, mark it unverified and SKIP rather than infer.
